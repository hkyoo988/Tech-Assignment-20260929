## 구현 중 추가된 결정

| D17 | 실시간 전달 시점 | 이벤트 커밋 **후**(`@TransactionalEventListener(AFTER_COMMIT)`)에 상대 연결로 전송 | 롤백된 이벤트가 상대 화면에 보이는 일을 막는다 | **확정 (구현 완료)** |
| D18 | 전송 방식과 비즈니스 로직 분리 | REST와 WebSocket 모두 같은 `EventService.append()`를 호출 | 입구가 달라도 락·멱등·순서 규칙이 동일하게 적용된다 | **확정 (구현 완료)** |
| D19 | 서버 전용 이벤트 | `SESSION_STARTED`, `DISCONNECTED`, `RECONNECTED`는 클라이언트가 보낼 수 없음 | 서버가 판단해야 하는 사실(연결 상태 등)을 클라이언트가 위조하지 못하게 한다 | **확정 (구현 완료)** — REST·WebSocket 공통으로 `append()`에서 거부 |
| D20 | 발신자 식별 (WebSocket) | 메시지 본문이 아니라 **연결 시점의 userId**를 사용 | 본문의 userId를 믿으면 다른 사용자로 위장할 수 있다. (인증은 과제 비목표라 쿼리 파라미터로 대체) | **확정 (구현 완료)** |
| D21 | 참여자 id 전략 | `session_participant`는 BIGINT AUTO_INCREMENT + `UNIQUE(session_id, user_id)` | JPA 복합키(`@EmbeddedId`)의 복잡도를 피하면서 자연키 유일성은 DB가 보장 | **확정 (구현 완료)** |
| D22 | 세션 id 전략 | `chat_session.id`는 JPA가 생성하는 UUID (`GenerationType.UUID`) | URL에 노출되는 id라 추측이 어려워야 하고, id가 null인 상태로 `save()`해야 `persist`로 처리되어 불필요한 SELECT가 없다 | **확정 (구현 완료)** |
| D23 | 퇴장과 연결 | `LEFT`여도 WebSocket 연결은 유지 (종료 여부는 클라이언트가 결정). 세션 종료 시에는 서버가 연결을 닫음 | 참여 상태와 연결 상태는 다른 개념이다. 재입장도 같은 연결로 가능 | **확정 (구현 완료)** |
| D24 | 퇴장 중 이벤트 전달 | `LEFT` 상태에서도 연결이 살아 있으면 EVENT를 받고, 재연결 시 RESUME도 `lastSeq` 이후 전체를 보낸다 (참여 상태로 필터링하지 않음) | 1:1 대화의 이벤트는 두 참여자 모두 볼 권한이 있고, 필터링하면 클라이언트의 seq 연속성이 깨져 누락 판단이 어려워진다 | **확정 (구현 완료)** |
| D25 | `lastSeq` 관리 주체 | 클라이언트가 받은 최대 seq를 기억하고 재연결 시 전달. 서버는 사용자별 읽음 위치를 저장하지 않음 | 기기·탭마다 받은 위치가 다를 수 있고, 서버 저장 시 쓰기 부하가 늘어난다. 서버는 seq 이후 조회만 제공하면 된다 | **확정 (구현 완료)** |
| D26 | `at` 파라미터 형식 | `OffsetDateTime`(오프셋 필수)으로 받고 UTC로 변환해 비교 | 오프셋 없는 시각은 어느 시간대인지 모호하다 | **확정 (구현 완료)** |

## 결정 근거 메모

- **D2**: 1:1 서비스라 "누가 참여할 수 있는가"는 세션 생성 시 고정(불변 조건)이고, "지금 누가 들어와 있는가"는 이벤트에서 파생되는 값이다. 둘을 분리하면 앞의 것은 검증에, 뒤의 것은 빠른 조회(`GET /sessions?participant=`)에 쓴다.
- **D4**: 메시지 전송 직후 ACK가 오기 전에 사용자가 수정·삭제를 누를 수 있다. 클라이언트가 이미 아는 `clientEventId`를 식별자로 쓰면 서버 응답을 기다리지 않아도 된다.
- **D5**: 클라이언트 시계는 기기마다 다르고 조작 가능하다. 서버 seq는 락 안에서 발급되어 세션 내 전순서(total order)를 보장하고, 복원 시 같은 입력 → 같은 결과(결정성)를 만든다.
- **D7**: 1:1 채팅은 세션당 동시 쓰기가 많지 않아 락 경합이 작다. 낙관적 락은 충돌 시 재시도 로직이 필요해 구현 복잡도가 올라간다. (경합 측정 결과는 부하 테스트 후 보강)
- **D8**: 여러 서버 인스턴스의 시계가 조금씩 다르면 seq는 증가하는데 server_ts가 역전될 수 있다. `?at=` 복원이 seq와 모순되지 않게 세션 내에서 server_ts를 단조 증가로 보정한다.
